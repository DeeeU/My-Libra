# 認証アーキテクチャ

## 概要

My-Libra はオフラインファースト設計で、ログインなしでも従来通りローカルモードで利用可能。
Supabase GoTrue を使用した認証基盤により、クラウド同期・マルチデバイス対応を実現する。

## 認証方式

| 方式 | 実装状況 | 備考 |
|------|----------|------|
| メール/パスワード | 実装済み | 6文字以上のパスワード |
| Sign in with Apple | 実装済み | Apple Developer Account 必要 |
| Google ログイン | 将来対応 | Google Cloud Console 設定必要 |

## 認証フロー

```
LaunchScreenView (3秒アニメーション)
    │
    ▼
AuthGateView (認証状態チェック)
    ├── SupabaseManager.isLoading == true ──→ ProgressView
    ├── isAuthenticated == true ──→ ContentView (メインTabView)
    ├── isSkipped == true ──→ ContentView (ローカルモード)
    └── 未認証 ──→ AuthView
                     ├── LoginView (メール/パスワード + Apple)
                     └── RegisterView (新規登録)
                     └── 「ログインせずに使う」ボタン
```

## トークン管理

- **JWT**: Supabase がセッション管理
- **リフレッシュトークン**: 自動ローテーション有効 (`refresh_token_reuse_interval = 10`)
- **有効期限**: 3600秒 (1時間)
- **保存場所**: Keychain (supabase-swift SDK が自動管理)

## セッション管理

`SupabaseManager` が `authStateChanges` を監視し、以下のイベントを処理:
- `initialSession`: アプリ起動時のセッション復元
- `signedIn`: ログイン完了
- `signedOut`: ログアウト
- `tokenRefreshed`: トークン自動更新

## コンポーネント構成

```
SupabaseManager (@Observable シングルトン)
├── client: SupabaseClient
├── currentUser: Auth.User?
├── isAuthenticated: Bool
├── isLoading: Bool
└── メソッド: signUp / signIn / signInWithApple / signOut / fetchProfile / updateProfile

AuthViewModel (@Observable)
├── フォーム状態: email, password, confirmPassword
├── UI状態: isLoading, errorMessage, showError
├── バリデーション: メール空チェック、パスワード長、一致確認
└── Apple Sign In: nonce 生成、IDToken 処理

AuthGateView → 認証状態ルーティング
AuthView → ログイン/登録切り替えコンテナ
LoginView → メール/パスワード + Apple Sign In
RegisterView → 新規登録フォーム
ProfileView → 表示名編集 + ログアウト
```

## Nonce 処理 (Apple Sign In)

1. `SecRandomCopyBytes` で 32バイトのランダムノンス生成
2. SHA-256 ハッシュ化して Apple に送信
3. Apple から返却された `identityToken` + 元のノンスで Supabase に認証
4. Supabase GoTrue が検証 → セッション発行

## プロフィール管理

- `profiles` テーブルで `auth.users` を拡張
- 新規ユーザー登録時にトリガーで自動作成
- 表示名・アバターURL を保持
- SettingsView からアクセス可能
